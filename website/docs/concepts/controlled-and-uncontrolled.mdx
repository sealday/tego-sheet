# Controlled and Uncontrolled Workbooks

Choose one ownership model when `TegoSheet` mounts. Never pass both `document` and `defaultDocument`, and
never switch a mounted instance between controlled and uncontrolled mode. A mode change is a new
spreadsheet instance: unmount the old one or give the replacement a new React `key`.

## Uncontrolled ownership

With `defaultDocument`, the component owns subsequent state. Use `onDocumentChange` to persist snapshots
and a ref for occasional reads or commands.

```tsx
import { createSpreadsheetDocument, TegoSheet, type SpreadsheetDocument } from 'tego-sheet';
import 'tego-sheet/styles.css';

const initialDocument = createSpreadsheetDocument({ sheetName: 'Notes' });

export function UncontrolledSheet() {
  return (
    <div style={{ height: 480 }}>
      <TegoSheet defaultDocument={initialDocument} onDocumentChange={saveDraft} />
    </div>
  );
}

function saveDraft(document: SpreadsheetDocument) {
  localStorage.setItem('notes-workbook', JSON.stringify(document));
}
```

## Controlled ownership

With `document`, the parent owns the accepted snapshot. Apply the `onDocumentChange` snapshot to state. Keeping the
same object reference during unrelated parent renders avoids unnecessary external replacement work.

```tsx
import { useState } from 'react';
import { createSpreadsheetDocument, TegoSheet, type SpreadsheetDocument } from 'tego-sheet';
import 'tego-sheet/styles.css';

const initialDocument = createSpreadsheetDocument({ sheetName: 'Plan' });

export function ControlledSheet() {
  const [document, setDocument] = useState<SpreadsheetDocument>(initialDocument);

  return (
    <div style={{ height: 480 }}>
      <TegoSheet document={document} onDocumentChange={setDocument} />
    </div>
  );
}
```

Controlled mode is useful when another React view must own every accepted edit. Uncontrolled mode is
usually simpler when the workbook can own rapid editing state and the application only persists
committed snapshots.
